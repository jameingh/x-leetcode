# 第三阶段：决策空间的博弈艺术 —— 回溯搜索 (Backtracking)

如果说前面的算法是教你如何“高效地走一条路”，那么回溯算法就是教你如何**“系统性地穷举所有可能的路”**。它是解空间搜索的核心，是理解动态规划和复杂搜索算法的敲门砖。

## 1. 核心思维：决策树与“吃后悔药”

回溯算法的本质是 **深度优先搜索 (DFS)** 的一种特例。它的核心在于在一个巨大的“决策树”上进行探索。

**思维模型：迷宫探险**
你在一个分岔路口众多的迷宫里找出口：
1. **决策**：你在每个路口都要做一个决定——往左走、往右走还是往前走？
2. **深入**：你选择一条路（比如向左），并记录下你已经走过的路径。
3. **触底/撞墙**：
   - 没找到目标？你必须回到上一个路口，并**抹掉你刚才在那条死路上留下的足迹**（这就是“回溯”）。
   - 找到目标？记录答案，然后可能还要回到路口找寻下一个可能的答案。

**核心公式：路径 + 选择列表 + 结束条件**

## 3. 大脑模拟案例 (Brain Simulation)：n=3, k=2

为了不让代码显得抽象，我们在脑子里跑一下 `combine(3, 2)` 的过程：

1. **第一层递归 (start=1)**：
   - 选 `1`：`path=[1]`。**进入下一层 (start=2)**。
2. **第二层递归 (start=2)**：
   - 选 `2`：`path=[1, 2]`。长度达到 `k=2`！**记录并返回**。
     > **💡 [重要细节] 拍照存证：必须用 `path[:]` 或 `path.copy()`**
     > **否则 `result` 里存的只是同一个 `path` 对象的引用，回溯完会全变空。**
     > 
     > 伪代码：
     > ```python
     > if 终止条件:
     >     结果.append(path[:]) # 或者 结果.append(list(path)) 或 结果.append(path.copy())
     >     return
     > ```
   - **回溯**：`path.pop()` -> `path=[1]`。
   - 选 `3`：`path=[1, 3]`。长度达到 `k=2`！**记录并返回**。
   - **回溯**：`path.pop()` -> `path=[1]`。
   - 这层没得选了，返回上一层。
3. **回到第一层 (start=1)**：
   - **回溯**：`path.pop()` -> `path=[]`。
   - 选 `2`：`path=[2]`。**进入下一层 (start=3)**。
4. **第二层递归 (start=3)**：
   - 选 `3`：`path=[2, 3]`。长度达到 `k=2`！**记录并返回**。
   - **回溯**：`path.pop()` -> `path=[2]`。
   - 这层没得选了，返回。
5. **回到第一层 (start=1)**：
   - **回溯**：`path.pop()` -> `path=[]`。
   - 选 `3`：`path=[3]`。**进入下一层 (start=4)**。
6. **第二层递归 (start=4)**：
   - `4 > n`，直接退出。

**确定性选择**：你会发现，`startIndex` 就像是给你划了一道“不准回头”的警戒线。选了 `1` 就只能从 `2` 往后看；选了 `2` 就只能从 `3` 往后看。这直接剪掉了所有重复的分支！

## 4. 为什么需要“撤销选择”？

想象你在做“排列组合”题。你第一层选了数字 `1`。
- 如果不回溯，当你从深层递归回来准备尝试选数字 `2` 时，你的路径里还残留着之前的 `1`。
- **回溯（pop）的意义就是保持“案发现场”的绝对干净**，让每一层主管在做决定时，看到的都是相同的初始环境，而不是被前一个分身污染过的残局。

## 5. 全排列：无序搜索的艺术 (Permutations)

全排列问题与组合问题最大的不同在于：**顺序敏感**。

### A. 为什么不能使用 `startIndex`？
- **直觉**：`startIndex` 是一道“不准回头”的警戒线。在组合中，`[1, 2]` 和 `[2, 1]` 等价，所以我们强迫只选右边的数。
- **代价**：在排列中，如果你选了 `2` 就不准看 `1`，那么你永远搜不出 `[2, 1]`。
- **结论**：排列问题每一层循环都必须**从 0 开始**，即 `for i in range(len(nums))`。

### B. 如何防止“自己选自己”？
既然每一层都从头看，怎么保证不选到已经选过的数？
- **秘籍**：引入 `used` 布尔数组（或集合）。
- **逻辑**：每次想选 `nums[i]` 时，先看 `used[i]` 是否为真。如果是，说明这个数在当前路径的“上游”已经被用过了，跳过它。

## 6. 进阶：回溯的“剪枝”艺术 (Pruning)

如果在决策树中，我们已经预见到某条路径不可能产生答案，就应该果断“剪掉”这个分支，不再向下递归。

### A. 搜索范围剪枝 (适用于 77. 组合)
在 77 题中，如果剩下的元素个数已经不够凑齐 `k` 个了，我们就不应该再继续往后找了。这就是**“余粮检查”**。

- **思维模型：超市买可乐**
  如果你打算买 3 瓶可乐，但货架上只剩 2 瓶了，你根本不会去排队结账，而是直接转身离开。

- **公式推导 (从第一性原理出发)**：
  1. 我们还差几个数？ `needed = k - len(path)`。
  2. 如果我们走到位置 `i`，剩下可选的数（包含 `i`）有： `n - i + 1` 个。
  3. 必须满足：`n - i + 1 >= needed`，否则就是无效搜索。
  4. 变形得：`i <= n - needed + 1`，即 `i <= n - (k - len(path)) + 1`。
  5. **关键**：Python 的 `range` 是左闭右开，为了让 `i` 能取到那个最大值，停止位要再 `+1`。
  - **最终公式**：`for i in range(startIndex, n - (k - len(path)) + 2):`

- **直觉**：这行公式就像是在递归前的一道“快速安检”，直接砍掉了决策树末端的万千废枝。

### B. 总和剪枝 (适用于 39. 组合总和, 40. 组合总和 II)
当数组有序时，如果当前位置的数值加上当前总和已经超过目标值，由于后面的数值更大，必然也超重。
- **思维模型：限重电梯**
  如果电梯已经快满了，当前排队的人是个大胖子，他一上去就超重了，那他后面排队的胖子们也都不用试了。
- **逻辑表达**：在 `for` 循环中加入 `if current_sum + nums[i] > target: break`。
- **核心价值**：将“无效路径”在进入递归前从源头掐断。

### C. “树层”去重剪枝 (适用于 40. 组合总和 II)
当输入的数组中有重复数字时（如 `[1, 1, 2]`），如果不剪枝，会搜出两个 `[1, 2]`。
- **核心逻辑**：**先排序**。在同一个 `for` 循环里（同一树层），如果发现当前取的数和前一个数一样，就跳过。
- **判断句式**：`if i > startIndex and nums[i] == nums[i-1]: continue`
- **深度解析**：关于“树层去重”的具体演变过程，请参考 **[组合总和 II 动态分层演示指南](combination_sum_ii_40_visual.md)**。
- **区分点**：
  - **树层去重**：在“同一层”决策时，不选重复的（像是在选妃时拒掉双胞胎里的弟弟）。
  - **树枝深入**：在“深层”递归时，可以使用重复的数字。

### C. 子集问题的“全节点收获” (适用于 78. 子集)
与组合、排列不同，子集问题不需要等待“终止条件”。
- **核心逻辑**：只要进入递归函数，第一件事就是把当前的 `path` 放入 `result`。
- **直觉**：这就像是在决策树的每一个落脚点都插上一面旗帜，而不是只在山顶插旗。
